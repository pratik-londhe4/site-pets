# Site Pets (`site-pets`)

Namespace `PratikLondhe\SitePets`, prefix `site_pets`, CSS prefix `spets-`, JS hooks namespace `sitePets`. E2E port 8913.
Requires at least 6.6 and PHP 7.4.

## Problem

vscode-pets (4,000+ GitHub stars) shows that people love a small pixel pet keeping them company. Site owners want the same on their sites: a mascot that makes a personal blog, a portfolio or a kids' site feel alive, and logged-in users want a desk buddy in wp-admin.

Competitors (directory, Google, GitHub, 2026-10-24): Rayzee Pet Counter (0 installs, one walking pet plus a visitor counter), Cute Animals (30 installs, one cat walking left to right, upsells), Wapuu Dashboard Pet (50, static Wapuu in the dashboard), PetMySite (0, hosted chat-button mascot). None has several pets with behaviours, none walks on the page's own layout, none has a wp-admin buddy per user or a playground block. vscode-pets' art cannot be reused (the cat artist asked that it not be redistributed), so all art is original, generated by `tools/sprites/generate.py`.

## v1.0.0 scope

1. **Pets.** Cat (orange, grey, black), dog, fox, rubber duck, Wapuu. 32×32 pixel sprite sheets with idle, walk, run, sit, sleep, jump and fall frames, all generated from shapes by one script so the style is consistent. Each pet has a name (default per type, editable).
2. **Engine** (`assets/js/engine.js`, no DOM, unit tested in Node): a state machine per pet (idle, walk, run, sit, sleep, chase, fetch, fall), physics (gravity, landing, jumping between platforms), platforms read from the page (the top edges of visible headings, images, figures, buttons and the bottom of the viewport), seeded randomness so tests are deterministic.
3. **Front end** (`assets/js/pets.js`): pets in a fixed overlay that never blocks clicks (only the pets themselves take the pointer). Click a pet to pet it (heart), the ball button throws a ball the pets fetch, the hide button hides them for this visitor (remembered in localStorage, no cookie). Paused when the tab is hidden. With `prefers-reduced-motion`, pets sit still on the bottom edge and only react to clicks.
4. **Settings** (Appearance > Site Pets): on or off, which pets (up to 3), where (every page, the front page only, or chosen post types), on phones or not, the ball and hide buttons, a live preview. Stored in one option.
5. **wp-admin buddy**: each user chooses a pet and a name on their profile (or none). It walks along the bottom of the admin screen. Off by default for each user; site admins can disable buddies for everyone.
6. **Pet Playground block** `site-pets/playground`: a framed scene (garden, beach, night) with chosen pets playing inside it. Dynamic block, works with the site-wide pets off.
7. **Edge cases**: themes without `wp_footer` (pets do not load), page builders (overlay is outside the page DOM), RTL, 375 px, multisite (per site), caching plugins (no per-visitor PHP output).
8. **Privacy**: no personal data. The hide choice lives in the visitor's browser. Policy text says so.
9. **Uninstall**: deletes the option and every user's buddy meta.

## Hooks

Filters: `site_pets_capability`, `site_pets_types` (add custom pets with a sprite sheet and manifest), `site_pets_settings`, `site_pets_defaults`, `site_pets_show` (per request), `site_pets_max_pets`, `site_pets_scenes`, `site_pets_config` (what the front-end script gets), `site_pets_buddy_enabled`.
Actions: `site_pets_settings_saved`, `site_pets_buddy_saved`.
JS (`wp.hooks`, namespace `sitePets`): filters `sitePets.config`, `sitePets.platformSelector`, `sitePets.nextState`; actions `sitePets.ready`, `sitePets.petted`, `sitePets.ballThrown`, `sitePets.hidden`.

## Abilities

`site-pets/get-settings` (readonly), `site-pets/update-settings` (idempotent), `site-pets/list-pet-types` (readonly).

## WP-CLI

`wp site-pets status`, `enable`, `disable`, `set <pets>... [--where=] [--mobile=]`, `types [--format=]`, `buddy <user> <pet|none> [--name=]`.

## E2E ideas

- Default install: settings off until enabled? No: enabled with one orange cat, so activation shows something. Front page has the overlay and one pet; its sprite loads.
- Settings page saves pets, where and mobile; the option in the database matches (WP-CLI).
- "Front page only": a single post has no pets, no script.
- Clicking a link under a pet's path still navigates (overlay passes clicks).
- Hide button hides pets and they stay hidden after reload; nothing in the database.
- Reduced motion: pets do not move.
- Ball: thrown, a pet reaches it.
- Admin buddy: user meta saved from the profile page, buddy shows in wp-admin for that user only.
- Playground block renders its scene and pets, with site-wide pets off.
- Contributor cannot open the settings page.
- 6.6 / PHP 7.4, 6.9, latest.

## Hard parts

- Platforms from the layout: read once per scroll/resize frame (throttled), only elements in or near the viewport, merge overlapping edges, ignore tiny ones; pets keep their platform while it moves (scrolling).
- Sprite art: original, consistent across pets and frames, so it is generated from shapes.
- Zero cost when not visible: no work when the tab is hidden or the pets are hidden; a few kilobytes of JS; no layout shift.
